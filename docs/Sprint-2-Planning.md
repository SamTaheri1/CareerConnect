# Sprint 2 Planning

This is where all risks, priorities, effort estimation, and team capacities are planned for Sprint 2.

## Sprint Goal

For Sprint 2, we are continuing the development of CareerConnect by improving the features from Sprint 1 and implementing more of the main functionalities of the website.

We will focus on user profile and resume management, job searching and filtering, viewing job details, applying for jobs, and tracking applications. We will also work on recruiter features and additional user stories created by our team.

Another important goal is to test our features, fix bugs, set up continuous integration (CI), and keep our GitHub repository organized.

The main goal is to have all planned features implemented and tested by October 20, giving us time to review everything before the final deadline on October 25.

## Sprint Backlog

For Sprint 2, we need to implement and test the main features of CareerConnect while keeping the project organized.

The work planned for this sprint is:

- Improve user registration, login, and logout.
- Complete user profile creation and editing.
- Implement resume upload, replacement, and removal.
- Display available jobs and their information.
- Implement job searching and filtering.
- Allow users to view job details.
- Implement job application submission and tracking.
- Work on the database and test data persistence.
- Implement recruiter features.
- Implement additional user stories created by the team.
- Create acceptance tests for the user stories.
- Test features and fix bugs discovered during testing.
- Set up continuous integration (CI).
- Improve README instructions.
- Update Sprint Planning and the GitHub project board.
- Keep meeting minutes and AI Usage Logs updated.
- Record individual team contributions.
- Prepare the Sprint 2 demonstration and summary report.

## Priorities

For Sprint 2, we want to focus first on completing the required features and making sure they work correctly.

## Risks

There are a few things that could make Sprint 2 harder for our team.

Since Sprint 2 lasts only two weeks, we have limited time to complete the required work. We also have midterms, assignments, and different schedules, which can make it difficult to meet and work together.

Another risk is that some features are more complicated than others, especially when connecting the frontend, backend, and database. Testing can also reveal bugs that require additional time to fix.

There could also be problems with GitHub coordination, especially when several team members are working on different parts of the project.

To reduce these risks, we will divide the work between team members, communicate regularly, prioritize the required features, test our work, and help each other when problems appear.

Our target is to finish the planned work by October 20 so we have enough time to review and make corrections before October 25.

## Effort Estimation

- **Small:** README updates, meeting minutes, AI logs, minor bug fixes, and GitHub organization.
- **Medium:** Sprint Planning, user stories and tasks, acceptance testing, job searching and filtering, and CI setup.
- **Large:** Database work, profile and resume management, job applications and tracking, recruiter features, and implementation of additional user stories.
