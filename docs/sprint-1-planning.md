# Sprint 1 Planning
This is where all risks, priorities, effort estimation, and team capacities are planned.

## Sprint Goal

For Sprint 1, we are starting the main setup of CareerConnect and implementing the first features of the website.
We will set up the project on GitHub, divide the work between the team members, and start working on user registration and login, 
profile management, and resume upload and management. 
The main goal is to have the basic parts of the website started and working so we can build on them in the next sprints.

## Sprint backLog

For Sprint 1, we need to get the project organized and start working on the first features of CareerConnect.

The work planned for this sprint is:  

•	Set up the GitHub repository  
•	Add all team members to the repository  
•	Organize the project folders and files  
•	Create the README file  
•	Plan the sprint and divide the work between the team members  
•	Create and assign GitHub issues  
•	Create the user stories and break them into smaller tasks  
•	Decide how we will work together on GitHub  
•	Work on user registration and login  
•	Work on profile management  
•	Work on resume upload and management  
•	Test the features we complete  
•	Fix problems found during testing  
•	Keep track of AI use in the AI logs  
•	Keep meeting minutes for the team meetings  
•	Keep track of our progress on GitHub  


## Priorities
For Sprint 1, we want to focus first on the work that is needed to get the project started and the main features working.

### High Priority

•	Finish the GitHub setup  
•	Complete the README and Sprint Planning  
•	Prepare the user stories and related tasks  
•	Start the registration and login system  
•	Work on profile management  
•	Add resume upload and management  

### Medium Priority

•	Test the features that are finished  
•	Organize the project files  
•	Make sure the work is properly assigned and tracked  
•	Keep the meeting notes updated  
•	Keep the AI logs updated  

### Low Priority

•	Fix small issues that do not affect the main features  
•	Make small changes or improvements after the main work is done  

## Risks

There are a few things that could make Sprint 1 harder for us. Since everyone has different schedules, 
we might not always be free at the same time or able to meet when we want. Some of us may also need more 
help with certain parts of the project. Someone could also get sick, fall behind, become unavailable, or not do as much work as expected. If that happens, 
the rest of the team may have to help or take over some tasks. We could also have problems with the code, GitHub, or a technology we do not know very well. Some tasks might also take longer than we thought.

## Effort estimation

•	Small: GitHub setup, README, meeting minutes, AI logs  
•	Medium: Sprint Planning, user stories and tasks, profile management, testing  
•	Large: Registration and login, resume upload and management  

## Team capacity

Our team has four members. Three of us are in Software Engineering and one is in Computer Engineering. We are in second and third year, so we already know the basics of coding, but we are still fairly new and learning as we go.
Some parts of the project may take us more time because we are still getting used to certain tools and technologies. We are also still learning how to use AI properly, especially how to write better prompts and how to check if the answers it gives us actually make sense.
We will divide the work based on what each person is more comfortable with and help each other when someone needs it.
